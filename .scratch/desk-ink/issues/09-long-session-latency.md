# 장시간 연결 후 지연

Status: in-progress (Windows 최소화 지연 재현·수정; 회귀 검사와 iPad 조사 진행)
Blocked by: none
Review baseline: `b0ee492`

사용자 보고: 오래 연결하면 PC와 iPad가 다소 느려지며 USB 재연결 또는 iPad X→재연결로 회복한다. 아직 iPad를 업데이트하지 않은 상태에서 재발했다.

승인된 검증 범위는 `docs/verification-plan.md`의 연결→입력 반영, Windows 캡처→iPad 영상, 펜의 로컬/원격 표시 지연이다.

- [x] 사용자 연결을 유지한 채 프로세스와 기존 로그 확인.
- [x] 실제 움직이는 화면 수신 검사: 중앙값 57.8/58.7fps.
- [x] 합성 영상·입력 동시 전송 및 반복 수신 정지 검사. 같은 연결에서 회복하여 지속적 지연은 재현되지 않음.
- [x] 기존 수신 보고의 영상 지연·왕복 시간·조립 대기 깊이를 로그에 추가.
- [x] 호스트 라이브러리·예제 Release 컴파일 검사 및 진단 예제 포맷 검사 통과.
- [ ] 사용자 증상 재현 및 원인 분리.
- [ ] 재현된 원인에 대한 회귀 검사와 수정.
- [ ] 실기기 확인과 배포.

상세 조건과 측정 한계는 `docs/fps-diagnosis.md`의 2026-10-19 항목에 기록했다. 추가한 진단 코드를 성능 수정으로 표시하지 않는다. 사용자 앱 종료·필기 초기화·공개 파일 교체는 수행하지 않았다.

추가 답변: iPad 로컬 선까지 양쪽이 느린 경우와 Windows만 느린 경우가 모두 발생한다. 이 답변으로 입력 구분 질문은 해소됐다.

Windows 실제 창 검사에서 설정 창 최소화 시 표시된 필기의 나이가 p95 121.3/121.0ms로 두 번 실패했다(기준 50ms). 보이는 창은 37.5/39.8ms였다. eframe 0.36.2는 invisible/minimized 창의 갱신을 100ms로 제한하며 기존 필기는 `App::logic`에 묶여 있었다. `AnnotationSurface`가 전용 스레드에서 HWND 생성·메시지 처리·최신 보드 표시·임시 필기 만료·종료를 소유하게 변경했다. 수정 후 같은 검사는 보이는 창 18.8ms, 최소화 21.2ms로 통과했다. 실제 사용자 프로세스의 DeskInk 설정 창도 최소화 상태임을 HWND 열거로 확인했다.

새 표시는 기존 입력 세션과 화면별 필기를 유지하며, 표시 전 잠금 해제와 최대 한 개의 깨우기 신호로 입력 대기와 표시 작업 누적을 막는다. 입력·지우개·취소·숨기기 실제 픽셀 검사와 동시 입력 검사(p95 0.034ms)가 통과했다. 이는 Windows 문제 하나의 수정이며 양쪽이 함께 느려지는 모든 경우를 해결했다는 주장은 하지 않는다.
