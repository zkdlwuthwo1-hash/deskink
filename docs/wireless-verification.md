# DeskInk 0.5.0 Wi-Fi/LAN 검증 기록

2026-10-21 기준 진행 중인 검증 기록이다. **아래의 통과 결과는 각 실행 시점의
소스에 대한 결과이며, 검토 후 수정·최종 패키지·실기기 검증까지 완료했다는 뜻이
아니다.** 공개 배포 전 마지막 수정에 영향을 받는 검사를 다시 실행한다.

요구사항은 [무선 연결 티켓](../.scratch/desk-ink/issues/11-wireless.md), 기존 승인된
검사 경계는 [검증 계획](verification-plan.md)에 있다. 비교 기준은
`36a09eeb022b6ab951808a66dfdb7de2ca7bf0a9`이다.

## 구현과 검사 경계

Windows에서 `Wi-Fi / LAN`을 펼쳐 `Allow Wi-Fi / LAN`을 켰을 때만 네트워크로
접속할 수 있다. 기본은 꺼짐이며 USB는 기존 설정으로 사용한다. iPad는 주소만
담긴 QR 또는 직접 IP 입력, Android는 직접 IP 입력으로 PC를 선택한다. 처음
등록할 때는 기존 6자리 코드가 별도로 필요하다. Wi-Fi에는 Windows와 태블릿 앱
모두 0.5.0이 필요하고, 이전 태블릿 앱의 USB 연결은 유지한다.

영상은 기존 UDP 전송·패킷 간격 조절·혼잡 피드백 경로를 사용한다. 필기는 별도의
확인 응답 채널을 사용하며, 정상 순서의 입력은 기다리지 않고 바로 적용한다.
손실·중복·순서 뒤바뀜을 복구하되 대기량과 입력 나이를 제한한다. USB 영상 압축,
필기 프레이밍, 재전송 없는 USB 경로를 무선 동작으로 바꾸지 않는다.

필기 검사의 경계는 실제 입력 메시지 → 인증·순서 판정 → 보드 변경·확인 응답이다.
전송 검사는 실제 UDP 소켓과 `start_sender`를 통과해 페어링, 영상 페이로드,
현재 연결의 필기를 확인한다. 이것은 무선 공유기·태블릿 하드웨어·Zoom이 포함된
실제 펜 지연 측정과 별개다.

프로토콜 제한은 다음과 같다.

- `HELLO2` 필기 기능 비트는 `FEATURE_RELIABLE_INK = 0x0010`, 호스트 기능 비트는
  `0x8000`이다. 필요한 기능을 지원하지 않는 네트워크 클라이언트는 허용하지 않는다.
- 무선 필기는 `DI02` + 기존 버전 1 JSON이며 JSON은 최대 1,024바이트다.
  USB는 기존 `DI01`을 유지한다.
- `DA02` 확인 응답은 정확히 20바이트이며 세션, 스트림 세대, 연속 적용한 마지막
  순번을 담는다. 현재 peer·session·epoch에 해당하는 입력만 적용한다.
- 대기·재정렬 창은 최대 256개다. 첫 전송은 즉시 하고 누락된 입력은 약 20ms
  간격으로 다시 시도한다. 가장 오래된 미확인 입력이 250ms에 도달하면 연결을
  끝내며, 오래된 필기를 몇 초 뒤 한꺼번에 재생하지 않는다.

## 테스트를 먼저 추가한 기록

- `wireless-host-red.log`: `AnnotationState::receive_lan`이 없는 상태에서 새 입력
  경계 검사가 컴파일 실패했다. 구현 후 동일 검사와 USB 세션 6개가 통과했고,
  이후 인증·크기·입력 나이 제한을 포함한 무선 필기 3개로 확장했다.
- `wireless-transport-red.log`: `SharedControl::lan_enabled`가 없는 상태에서
  네트워크 기본 비활성화·실제 UDP 통합 검사가 컴파일 실패했다. 구현 후
  `wireless-transport-green.log`의 20개 통합 검사가 통과했다.
- `wireless-frame-sequence-red.log`: 실제 UDP 전송 검사에서 LAN 프레임 순번의
  기대값 `1` 대신 캡처 순번 `7`을 받아 실패했다. 컴파일은 6분 38초 걸렸고
  검사는 실행 후 0.56초에 실패했다. LAN에 별도 연속 순번을 부여하는 수정 후
  `wireless-frame-sequence-green.log`의 재검사는 아직 진행 중이다.
- iPad 입력 대기열은 큐 진입 전 개수·입력 시각을 제한하고 공개 경계 검사를
  추가했다. 코드 후속 검토는 통과했으나, 최종 수정본의 CI 결과가 나오기 전에는
  해당 검사의 실패→통과 결과를 확정하지 않는다.

첫 두 항목은 새 공개 경계가 존재하지 않아 실패한 기록이다. 이미 존재하던 기능의
실행 중 오류를 재현한 것처럼 해석하지 않는다.

## Standards

독립 검토에서 다음 2개 항목을 보고했다. 저장소 지침과 별개로 적용한 코드 냄새
기준은 판단을 돕는 기준이며, 자동으로 강제 위반으로 간주하지 않는다.

1. **P2, 코드 수정·후속 검토 완료:** iPad `ControlChannel.swift`의 `queue.async`가 무선 필기를
   무제한으로 먼저 쌓을 수 있고, `ReliableInkSender.swift`의 입력 나이는 그
   작업이 실행된 뒤 시작한다. 송신 창의 256개·250ms 제한만으로는 앞단 대기를
   제한하지 못하던 문제였다. 무선 입력을 큐에 넣기 전부터 개수와 최초 입력
   시각을 추적하고, 그 시각을 송신 창까지 전달한다. 후속 검토에서 수정됨을
   확인했으며 공개 경계 회귀 검사를 포함한 최종 CI 결과는 기다리고 있다.
2. **낮은 우선순위 권고, 유지:** Android `MainActivity`에서 USB/LAN에 따른
   종료·키프레임 요청·필기 바인딩·클라이언트 생성 분기가 반복된다. 공통
   인터페이스가 분기를 줄일 수 있으나, 동작이 좋은 USB 경로를 보존하는 이번
   범위에서는 광범위한 추상화 변경을 미룬다.

검토에서 다른 인증·세션·스트림 세대·모니터·기본 비활성화·USB 보존 문제는
추가로 보고하지 않았다. 후속 검토에서도 새 문제를 보고하지 않았다.

Standards: 총 2개 중 가장 높은 P2는 코드 수정·후속 검토 완료, 낮은 우선순위 권고 1개는 유지한다. 최종 CI는 별도로 확인한다.

## Spec

같은 기준점에서 요구사항 충족 여부를 별도로 검토하여 다음 2개 항목을 보고했다.

1. **P1, 코드 수정·후속 검토 완료:** Android `UdpFrameAssembler`는 영상 순번이 직전 값 + 1일
   것을 요구하지만 Windows는 캡처 단계의 순번을 그대로 보낸다. 캡처를 건너뛰어
   정상 영상이 10 → 12로 전송되면 클라이언트가 손실로 판단해 약 50ms 뒤
   폐기·키프레임 요청을 반복할 수 있던 문제였다. LAN 전송 영상에 연속된 순번을
   붙이고 USB 번호 동작은 유지하도록 수정했다. 실제 UDP 회귀 검사는 수정 전
   실패를 확인했으며 수정 후 재검사 결과는 아직 기다리고 있다.
2. **P2, 코드 수정·후속 검토 완료:** iPad의 무제한 앞단 입력 큐와 늦게 시작하는 나이 측정이
   “대기를 제한하고 오래된 필기를 재생하지 않는다”는 요구사항을 충족하지 못한다.
   큐 진입 전부터 제한하도록 수정했다. 같은 결함을 Standards에서도
   발견했으나 두 검토의 결과는 독립적으로 기록한다.

다른 인증·세션·스트림 세대·모니터·기본 비활성화·USB 보존 문제나 요구하지 않은
기능 확대는 추가로 보고하지 않았다. 두 검토자는 후속 코드에서 P1·P2 수정과
추가 문제 없음을 확인했다. 이 검토 통과를 최종 자동 검사나 실기기 확인의
통과로 대신하지 않는다.

Spec: 총 2개 중 가장 높은 P1과 P2 모두 코드 수정·후속 검토 완료다. 관련 재검사는 진행 중이다.

## 패키지와 공개 배포 전 확인

아래 항목은 현재 미완료다. 기존 0.4.4 패키지의 검증 결과를 0.5.0에 재사용하지 않는다.

- 최종 수정본의 Windows Release 빌드와 새 ZIP을 생성한다. 실행 중인 사용자의
  기존 DeskInk를 중단하거나 파일을 덮어쓰지 않고 별도 빌드 경로를 사용한다.
- ZIP 무결성·허용 파일 목록·모든 manifest 해시·빌드 소스·실제 exe 일치·포함 HTML을
  확인한다. 공백이 있는 새 경로에서 개발 SDK 없는 환경의 `-CheckOnly`를 실행한다.
- 최종 iPad CI와 IPA의 버전·번들 ID·빌드 정보, Android 최종 CI 및 APK의 버전·기존
  서명 인증서 일치·서명·정렬을 확인한다. 실패한 CI에서 나온 파일을 출시본으로
  확정하지 않는다.
- Windows ZIP·IPA·APK·안내서의 SHA-256을 확정하고 업로드 후 실제 다운로드와
  대조한다. GitHub Pages의 기본 링크와 기존 공유 링크에 최신 안내가 나오는지
  확인한다. 원본 개인 화면·접속 주소·계정·토큰·서명 키는 공개하지 않는다.

## 실제 기기 확인 목록

아래는 자동 검사로 대체할 수 없는 항목이며 **아직 실기기 확인하지 않았다.**
모델·OS·PC/GPU·공유기·접속 방식·영상 설정과 함께 결과를 기록한다.

1. 기존 USB 연결로 현재 동작을 확인한다. 같은 PC·태블릿·해상도·FPS 설정으로
   비교하고, Windows 0.5.0에서 이전 태블릿 앱의 USB 연결도 확인한다.
2. Windows와 태블릿을 0.5.0으로 업데이트한다. USB를 빼고 연결을 종료한 뒤
   Windows의 `Wi-Fi / LAN`을 펼쳐 접근을 켠다. PC 이더넷 + 태블릿 Wi-Fi와
   양쪽 Wi-Fi를 각각 확인한다. 신뢰하는 같은 로컬 네트워크에서만 검사한다.
3. iPad QR과 직접 IP, Android 직접 IP를 각각 사용한다. 처음 등록은 6자리 코드,
   등록한 PC의 재접속은 기존 등록으로 연결되는지 확인한다. iPad 로컬 네트워크
   권한 거부·허용, 잘못된 IP·포트·코드에 대해 안내가 맞는지 확인한다.
4. PC 두 대를 한 번에 한 대씩 전환하고 Screen 1 → 2 → 1을 오간다. 두 PC의 등록과
   각 화면의 필기가 섞이지 않는지, 이전 연결의 늦은 입력이 새 화면에 적용되지
   않는지 확인한다.
5. 펜·형광펜·지우개·레이저·사라지는 펜·실행 취소·다시 실행·전체 지우기를 양쪽
   화면에서 확인한다. Apple Pencil 두 번 탭, S펜 버튼을 누르는 동안 지우개 및
   놓았을 때 이전 도구 복귀, 손바닥과 두 손가락 확대·이동을 확인한다.
6. 잠자기·깨어나기, 앱 닫기·다시 열기, 짧은 Wi-Fi 끊김과 재접속, PC 주소 변경을
   확인한다. 오래된 필기가 뒤늦게 몰아서 나타나지 않아야 한다. 네트워크 접근을
   끈 뒤 USB로 돌아가 기존 동작을 다시 확인한다.
7. 지연을 비교할 때는 같은 필기 동작을 고속 카메라로 촬영해 펜 접촉→태블릿 화면,
   펜 접촉→Windows 화면을 구분한다. 평균뿐 아니라 느린 구간과 끊김을 기록한다.
   영상 디코더 FPS를 펜 전체 지연으로 간주하지 않는다. 아직 측정값이나 지연 0을
   보장하는 결과는 없다.
8. 30~60분 연속 사용하며 양쪽 필기·영상 반응이 누적해서 느려지는지 확인한다.
   Zoom에서는 필기할 모니터 전체를 직접 공유하고 다른 참가자 화면에서 필기·
   포인터를 확인한다. Zoom 전송 지연은 DeskInk 로컬 지연과 별도로 기록한다.

Windows 방화벽은 배포 폴더의 `bin/deskink.exe`, 표시된 UDP 포트(기본 9876),
개인 네트워크·로컬 서브넷으로 제한한다. 방화벽 전체를 끄거나 공유기 포트 포워딩을
설정하지 않는다. 화면과 필기 트래픽은 암호화되지 않으며, 게스트 Wi-Fi·기기 간
통신 차단·기관의 네트워크 정책은 연결 가능 여부와 실측 지연에 영향을 준다.
