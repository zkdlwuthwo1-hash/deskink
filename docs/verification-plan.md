# 승인된 테스트 범위

요청된 tdd 스킬은 테스트할 공개 접점(seam)을 사용자와 먼저 합의하도록 요구합니다. 아래 범위를 제시한 뒤 2026-10-16 사용자의 “뭐야 계속 진행”으로 승인받았습니다. 이 범위 안에서는 반복 확인 없이 테스트와 구현을 진행합니다.

## 자동 테스트의 공개 접점

공개 접점은 앱의 실제 호출자가 사용하는 입구와 결과입니다. 내부 함수 호출 횟수를 맞추는 테스트 대신 실제 입력과 관찰 가능한 결과를 검사합니다.

| 접점 | 검증할 동작 | 잡는 문제 | 이 테스트만으로 알 수 없는 것 |
|---|---|---|---|
| 필기 세션: 입력 → 표시 상태 | 선 시작·이동·종료, 도구 전환, 지우기, 숨기기, 실행 취소·다시 실행 | 누락·중복 필기, 잘못된 도구 동작, 상태 불일치 | GPU에서 실제 선이 표시되는 시간과 품질 |
| 확대된 입력 화면 → 세션의 모니터 좌표 | 화면 맞춤, 확대·이동, 회전·크기 변경 후 실제 필기 입력 경로 | 오프셋, 비율, 선택 모니터·DPI 변경에 따른 위치 오류 | 실기기 제스처 인식과 펜 촉감 |
| 연결 수신 → 세션 반영 및 응답 | 유효한 이벤트, 중복·잘못된 순서·잘린 메시지, 재연결, 입력 크기 제한 | 다른 PC에 쓰기, 반복 적용, 손상 입력에 의한 상태 오염 | USB 드라이버, 실제 네트워크 지연, 전체 보안성 |
| PC별 세션 저장 → 재시작 후 복원 | PC·모니터 분리, 원자적 저장, 손상된 저장 파일 대응, 일시 도구 만료 | 저장 유실·혼합, 재시작 시 오래된 레이저 복원 | 실제 전원 장애와 하드웨어 저장 장치 고장 |

각 접점의 인터페이스 이름과 자료형은 구현 언어에 맞춰 정합니다. 검증 범위는 위 동작으로 유지합니다. 순수 좌표 함수만 통과시키고 실제 입력 경로가 검증됐다고 판단하지 않습니다.

## 실기기에서 검사할 접점

| 실제 경로 | 확인할 결과 | 조건 |
|---|---|---|
| Windows 캡처 → iPad 영상 표시 | 선택 모니터 화면이 올바른 방향·비율로 표시됨 | Windows PC, 연결된 iPad, 지원 인코더 |
| Pencil 입력 → iPad 로컬 선 / Windows 선 | 로컬 반응과 PC 반영 지연, 영상으로 돌아오는 선의 중복·깜박임 | iPad/Pencil 및 양 화면을 함께 관찰할 수 있는 측정 수단 |
| Windows 필기층 → Zoom 상대 화면 | 선택 모니터의 필기·펜 포인터가 실제 수신자에게 보임 | 사용자가 직접 설정한 Zoom 공유와 수신 화면 |
| 지원 입력 장치 → 도구 동작 | 더블탭 지우개, 손바닥 구분, 손가락 확대, 비호버 기기의 포인터 | 해당 기능을 제공하는 실제 장치 |

## 지연 측정

- iPad에서 선이 나타나는 시간, Windows 반영 시간, 화면 영상 지연, Zoom 수신 지연을 구분합니다.
- 동일 장치·해상도·화면 배율·전원 조건에서 USB와 유선 연결을 비교합니다.
- 평균만으로 판단하지 않고 중앙값, p95, 최댓값, 끊김 발생을 기록합니다.
- 두 기기의 시계를 동기화하지 않은 상태에서 타임스탬프 차이를 편도 지연으로 해석하지 않습니다.
- 펜 접촉에서 실제 픽셀 표시까지는 양 화면 촬영 등 외부 관찰로 확인합니다. 계측 이벤트 시간은 처리 구간 측정으로 별도 표시합니다.
- 아직 성능 수치가 없으며, 수치 목표 달성 여부를 주장하지 않습니다. 첫 실기기 측정에서 병목과 개선 목표를 정합니다.

## TDD 실행 순서

1. 합의된 접점에서 실제 동작 한 가지를 검증하는 실패 테스트를 작성하고 실행합니다.
2. 해당 실패를 해결하는 최소 구현을 추가하고 통과를 확인합니다.
3. 다음 동작으로 반복합니다. 모든 테스트를 미리 대량 작성하지 않습니다.
4. 작업별 검증 후 실제 코드 검토에서 구조를 개선하고 관련 회귀 테스트를 실행합니다.

기대값은 구현을 그대로 계산해 복사하지 않고, 요구사항의 구체적 예나 독립적으로 확인한 값에서 가져옵니다. 플랫폼·시간·파일시스템 등 외부 접점만 필요한 범위에서 대체하고 내부 구현을 목으로 바꾸지 않습니다.

## 완료 표시 원칙

- 자동 테스트 통과, Windows 빌드 성공, iPad 빌드 성공, 실기기 확인, Zoom 수신 확인을 각각 기록합니다.
- 수행하지 못한 검증은 미실시로 남깁니다.
- 오류는 재현 → 최소화 → 원인 가설 → 측정 → 수정 → 회귀 확인 순서로 다룹니다.
- 보안 검토는 입력 검증·연결 인증·저장 범위·의존성에 대한 실제 확인을 기록하며, 일반 진단 스킬만으로 보안 인증을 받았다고 표시하지 않습니다.
